# mini

阶段 4 的产物：把阶段 0 那 50 行循环扩成一个能用的小框架。

毕业标准是**它能跑通主线项目的 v2 场景** —— 不是写一堆抽象，是真能替代 `src/agent.ts`。

## 为什么自己造

前面三个阶段刻意没用框架，因为「框架解决的是你还没遇到的问题」。现在问题遇齐了：
终止条件、工具注册、上下文压缩、中断恢复、子 agent。造一遍才知道那些框架的
API 为什么长成那样。

## 四个文件

| 文件 | 管什么 |
|---|---|
| `registry.ts` | 工具注册：定义、校验、执行收在一处 |
| `session.ts` | 会话状态：消息历史、快照、中断恢复 |
| `context.ts` | 上下文压缩：历史太长时怎么裁 |
| `loop.ts` | 循环本体：把上面三样串起来 |

## 和 src/agent.ts 的区别

`src/agent.ts` 是**专用**的：工具写死三个、终止条件写死四道、SYSTEM_PROMPT 是 DTO 专用的。
`mini/` 是**通用**的：工具从注册表来、终止条件可配、prompt 由调用方给。

代价是抽象层次多了一层。值不值得取决于你有几个 agent —— 一个的话 `agent.ts` 那样更直白。
