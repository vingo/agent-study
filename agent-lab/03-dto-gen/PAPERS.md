# 三篇论文的要点

阶段 4 的论文精读。只记对工程决策有影响的部分，完整内容看原文。

## ReAct（Yao et al., 2022, arXiv:2210.03629）

**最反直觉的一点：ReAct 在 HotpotQA 上输给了纯 CoT。**

PaLM-540B prompting 结果：

| 方法 | HotpotQA (EM) | FEVER (Acc) |
|---|---|---|
| Standard | 28.7 | 57.1 |
| CoT | 29.4 | 56.3 |
| CoT-SC（21 次采样） | 33.4 | 60.4 |
| Act-only | 25.7 | 58.9 |
| **ReAct** | **27.4** | **60.9** |
| ReAct → CoT-SC | 35.1 | 62.0 |
| CoT-SC → ReAct | — | 64.6 |
| 监督 SoTA | 67.5（~140k 样本） | 89.5（~90k 样本） |

ReAct 只在 FEVER（事实核查，需要外部 grounding）上赢。最好的方案是两者结合。

人工分析 200 条轨迹的失败模式表，比主结果更有用：

| | ReAct | CoT |
|---|---|---|
| 成功且推理正确 | 94% | 86% |
| 成功但靠幻觉 | 6% | 14% |
| 失败：推理错误 | 47% | 16% |
| 失败：检索结果没用 | 23% | — |
| 失败：幻觉 | — | 56% |

**工具把幻觉换成了另一种失败。** CoT 56% 的失败来自幻觉；ReAct 几乎没幻觉，但推理错误从 16% 涨到 47%，还多了 23% 的「检索到无用内容后走不出来」。论文的解释是结构化约束（thought-action-observation 必须交替）降低了推理灵活性。

对我们的意义：`search_files` 的价值不只是省 token。23% 的失败源于检索质量 —— 工具返回什么内容决定 agent 能不能自我纠正。这给阶段 1 那条「返回值是给模型的下一步指令」提供了量化支撑。

另一个数字：**3000 条轨迹微调后，PaLM-8B 的 ReAct(30.2) 超过所有 62B prompting 方法**，62B 微调(35.1) 超过所有 540B prompting。提示工程有天花板，撞到之后微调收益跨量级。

还有个消融值得记：ReAct(71%) vs ReAct-IM(53%) 在 AlfWorld 上。ReAct 稀疏灵活的思考胜过 Inner Monologue 式的密集反馈 —— 不是想得越多越好。

## Reflexion（Shinn et al., 2023, arXiv:2303.11366, NeurIPS 2023）

三个角色：

- **Actor** 生成动作轨迹
- **Evaluator** 打分。编程任务上用**单元测试**，推理任务用 exact match，决策任务用启发式规则
- **Self-Reflection** 把分数翻译成自然语言教训，存进 episodic memory

**关键：Evaluator 用的是客观判据。** Reflexion 不替代 oracle，它把 oracle 的信号翻译成更有指导性的形式。我最初理解反了，README 里有更正记录。

成绩：

| benchmark | Reflexion | GPT-4 基线 |
|---|---|---|
| HumanEval Python | 91.0% | 80.1% |
| HumanEval Rust | 68.0% | 60.0% |
| MBPP Rust | 75.4% | 70.9% |
| LeetcodeHardGym | 15.0% | 7.5% |
| **MBPP Python** | **低于基线** | — |

最后一行最重要：**MBPP Python 上 Reflexion 输了**，原因是自生成单测假阳性率太高。论文结论是「框架对评估质量有依赖」。消融实验也显示单测生成和自我反思两个组件缺一不可。

其他数字：AlfWorld 比 ReAct-only 提升 22%（**跑 12 轮之后**），HotpotQA 提升 20%。

「12 轮之后」是判断要不要用它的关键 —— 收益来自多轮试错累积。单轮通过率已接近 100% 的任务没有失败可迭代，多花的调用零回报。

它的「学习」发生在 prompt 里不在权重里，这正是 `mini/session.ts` 在做的事。区别是我们存原始 messages，它存提炼后的教训 —— 后者省上下文但多了「提炼可能出错」的风险。

## Toolformer（Schick et al., 2023, arXiv:2302.04761, NeurIPS 2023）

和前两篇不是一类：前两篇是 prompting 方法，这篇是**训练方法**。

机制：让模型在文本里自己插 API 调用候选 → 执行 → 只保留能**降低后续 token perplexity** 的那些 → 拿这批数据微调。判据是

```
L(有API有结果) < min(L(有API无结果), L(无API))
```

妙处是不需要人工标注、也不需要知道正确答案 —— 只需要知道「插进去之后后面的文本是不是更好预测」。6.7B 的 GPT-J 微调后在 ASDiv 上超过 175B 的 GPT-3。

但局限恰好解释了为什么这条路我们用不上：

- **不能链式调用** —— 每个 API 调用独立生成，一个工具的输出不能当下一个的输入
- **不能交互式使用** —— 搜索引擎返回几百条结果这种场景处理不了
- **对措辞敏感** —— 换个说法就可能不调用
- **样本效率低** —— 要大量文档才凑出少量有用的 API 调用
- **不考虑工具成本** —— 决定调用时不管这个调用贵不贵

前两条是致命的。我们的 v3 场景就是链式加交互：`list_files` 的结果决定读哪个文件，读到的内容决定搜什么。

它回答的是另一个问题：工具使用能不能内化进模型？能，但代价是失去动态性。

## 三篇串起来的线

ReAct 解决「怎么在推理中穿插动作」，Reflexion 解决「失败之后怎么改」，Toolformer 解决「工具知识能不能进权重」。

共同的隐含结论，也是最该带走的：

> **agent 的能力上限由环境反馈的质量决定，不是由模型的聪明程度决定。**

ReAct 23% 的失败来自检索无用内容；Reflexion 在 MBPP 掉分因为自生成单测假阳性；Toolformer 的整个训练信号就是 perplexity 这一个反馈。

这正是 `verify.ts` 和 `assert.ts` 那两道关的意义 —— 它们就是 Evaluator。而我们实测到的「判据漏检 namingStyle 导致 agent 盲考」，是同一条原理的具体形态。
